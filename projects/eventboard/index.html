The original EventBoard began as a team graduation project at Taibah University, which I led. I wanted to solve a familiar problem: discovering a pottery workshop in Madinah only after it had ended.

I later rebuilt the concept independently into a full-stack app for Arabic-first event discovery, transactional reservations and organizer reporting.

Behind every seat.

Finding an event is quick. Reserving the last seat must still be correct.

React and TypeScript serve visitors and organizers; Node.js, Express and PostgreSQL manage accounts, events and tickets. A Python service experiments with discovery, recommendations, demand gaps and registration forecasts.

Discover

Arabic normalization and BM25 plus character n-grams support event search. Hybrid recommendations provide readable reasons.

Reserve

PostgreSQL transactions lock inventory. Six simultaneous requests for three seats did not oversell.

Understand

Organizer analytics use synthetic interest and booking signals; predictive outputs are experimental.

AI, with limits.

Search and ranking

Arabic retrieval mixes BM25 and character n-grams. Recommendations blend multiple signals, but lack a ranking benchmark on real user behavior.

Synthetic forecasts

A model evaluated on 800 synthetic events achieved MAE 10.23 versus 18.29 for a category-mean baseline. This is not real-world forecasting accuracy.

Verified boundaries

An optional Claude assistant was tested with mocks, not a live key. Deterministic search and fallbacks remain if the AI service is unavailable. Methodology ↗
